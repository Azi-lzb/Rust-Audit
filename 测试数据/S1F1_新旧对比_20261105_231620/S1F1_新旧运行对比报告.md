## 输出对齐

- 两端审核结果中，3140 条记录逐列完全一致；3171 条记录的“文件、工作表、位置、异常类型”一致。Python 独有 476 行，Rust 独有 143 行。
- 94 本 Rust 已完成文件中，80 本与 Python 异常总数一致；另外有 14 本数量不一致。全体 129 本中按数量计 83 本相同（其中包含 3 本 Rust 失败但两端异常数恰为 0 的文件）。
- 35 本 Rust 失败文件在 Python 结果中包含 445 条异常（155 条公式异常、290 条条件格式异常），这些未进入 Rust 汇总结果。
- Rust 在已完成文件中另报 112 条 Python 未报的公式异常：金融基础数据-个人贷款 65 条、金融基础数据-单位贷款 37 条、金融基础数据-票据业务比 Python 多 10 条。需逐条人工判断是 Rust 误报、Python 漏报还是计算引擎结果差异。
- 另有 31 条记录的文件/工作表/单元格/类型相同，但说明或数值字段不同。

## Rust 失败原因

- 7 本金融基础数据采集（债券业务）：Umya 因源工作簿包含未验证的 `xl/externalLinks` 部件而安全拒绝写入；没有移除安全检查。
- 28 本公式复制后校验不一致：单位存款、同业业务、委托贷款、股权及特定目的载体投资各 7 本。校验定位到公式位置或公式文本与来源不一致，因保留写后验证而停止。
- 传入默认外部参照表后，Rust 的待人工重算数从无外部表诊断运行的 27 降为 0；因此前一轮无外部表的运行不作为新旧主对比结论。
