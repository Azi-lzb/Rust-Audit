# 新旧 Audit 性能对比（2026-10-29）

同一份合成输入分别经旧 Python 服务（进程内计时）与新 Rust CLI（子进程墙钟）运行，
每项 3 轮取最优。驱动与明细：`audit-core/tests/compare/perf_compare_20261029.py`、
`probe/reports/perf_comparison_20261029.json`。

## 结果总表（最优轮，毫秒）

| 功能 | Python | Rust | 加速比 | 输入规模 |
| --- | --- | --- | --- | --- |
| S3-F4 本期数值核对 | 6040 | 957 | **6.31x** | 10k 行 CSV |
| S3-F2 比较文件→说明文件 | 1920 | 222 | **8.64x** | 5000 行 / 1667 选中 |
| S3-F5 比较文件→金融表单 | 2021 | 887 | **2.28x** | 30 机构 × 40 指标 × 4 表（输出 30 工作簿） |
| S3-F1 两期数据→比较文件 | 1114 | 1483 | 0.75x（Rust 较慢） | 10k 行 CSV |
| S1-F1 真实公式重算子步骤 | 4658 | 6300 | 0.74x（口径不同，见下） | 7,200 个 VLOOKUP |
| S5 配置化逐笔统计审核 | 22.9 | 56.9 | 0.40x | 单文件 + 独立上期 |
| S2 报表采集审核 | 12.8 | 38.2 | 0.33x | 2 份真实夹具报表 |
| S1-F2 汇总校验结果说明 | — | — | SKIPPED | 本轮未执行计时；原跳过理由已更正，见下 |

参考开销：Rust CLI 进程启动 9.5 ms；Python 解释器启动 39.5 ms（未计入 Python 进程内计时）。

## 解读

1. **计算密集的大表功能 Rust 优势明显**：S3-F4 的跨期校验公式求值（6.3x）、
   S3-F2 的说明导出（8.6x）、S3-F5 的表单批量生成（2.3x，输出 30 个工作簿）。
   输入规模越大差距越大（S3-F2 在 5k 行时 Python 已近 2 秒）。
2. **S3-F1 是唯一 Rust 较慢的大表功能**（0.75x）：10k 行时 Python 进程内服务
   有暖机与免序列化优势；Rust 每轮为全新进程（含启动 9.5ms 与结果工作簿写入）。
   差距约 370ms，属工程优化空间（如结果写出路径），不是架构性劣势。
3. **S1-F1 的重算由 Excel 本身主导**：Python=pywin32 裸重算 4.7s，Rust=sidecar
   全管线 6.3s——Rust 侧额外包含公式缓存清理（OOXML 重写）、重算结果校验与
   原子发布，且每次为全新 Excel 实例；Python 侧未做这些步骤。两者驱动的都是
   同一个 Excel 引擎，纯 Excel 重算耗时两端一致；差异来自通道附加工作，
   而 Rust 的附加工作正是旧 Python 流程缺 validating 的部分。
4. **小负载（S5/S2）Rust "变慢"是启动与配置加载占比问题**：绝对差约 20–40ms；
   Python 计时未含解释器启动 39.5ms，若计入则 S5 基本持平、S2 差距缩小到 ~15ms。
   真实批量场景（如 2026-10-27 真实 S2 批次 Python 服务阶段即 839ms）下占比更低。

## 对比口径与限制

- Python=进程内 `perf_counter`（不含解释器启动）；Rust=子进程墙钟（含启动）。
  两端输入逐字节相同；每轮均校验成功产出（S3-F5 两端各生成 30 个工作簿）。
- S1-F1 仅对比重算子步骤：完整 S1-F1 还含模板匹配/公式复制/异常提取，两端
  语义等价但入口不同（Rust 为 GUI worker，Python 为自有流程），未做整体计时。
- S1-F2 未计时。2026-10-30 更正：原报告把 S1-F1 的保存缓存诊断开关误称为 S1-F2 CLI，不能据此认定 S1-F2 两端业务不等价。Rust 的 `s1-region-summary` 是汇总入口；旧 Python 默认汇总路径和 Rust 当前汇总路径均读取已保存的值或公式缓存。旧版另有 Office 读取选项，Rust 对被消费区域的缺失或错误公式缓存会报错；这些差异不能替代同输入、同配置的业务对照。历史 JSON 原样保留，其中该条 `reason` 是当时错误的描述。
- 本轮为合成负载单机 Windows 实测；不构成 Linux/麒麟目标环境结论。
