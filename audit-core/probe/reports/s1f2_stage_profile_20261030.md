## 测量范围

复用既有 S1-F2 对拍驱动的合成夹具生成逻辑，但只执行 Rust Release CLI，不启动 Excel COM。输入为模板/映射配置 5,672 bytes、2 本源簿 5,429/4,938 bytes、3 张源工作表、5 行源数据；输出 2 张表、9 行汇总数据。阅读器为 Calamine + namespace-aware OOXML，写入器为 rust_xlsxwriter 0.101.0。

本次测量期间检测到 21 个 Excel COM 或 Rust-Tools XLS 转换相关后台进程，三轮数值均被 JSON 标记为 **不具备正式基线资格**。该探针仅补充 Rust 内部阶段分布，不产生新的 Python/Rust 倍率。既有 Python/Rust 三轮全输出对拍及 4,320/59 ms 中位数仍以[原结果](s1f2_perf_comparison_20261030.json)为准。

## 结论与限制

在此小型夹具中，Rust 业务阶段只有数毫秒，CLI 启动及未单列工作占更大比例；历史 Python 4.32 秒主要来自其 Excel COM 执行路径。由于后台负载活跃且阶段计时分辨率为整数毫秒，不把这些数值用于优化前后比较或正式性能基线。该结果没有显示可优先优化的 Rust 业务阶段，也不支持进一步细化到亚毫秒阶段。
