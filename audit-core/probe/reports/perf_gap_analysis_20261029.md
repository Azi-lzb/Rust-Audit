# Rust 较慢功能的差距分解与优化空间（2026-10-29）

基于 `perf_comparison_20261029` 结果的逐功能分解，全部数字为本机实测。

## 2026-10-30 后续实施状态

- **后续改动**：Windows S1-F1 默认路径已改为 Audit 自身的原生 COM 批次工作进程，不再调用 lo-convert 可执行文件；相关代码尚未编译、运行或计时。下方关于 sidecar 的当时描述只作为历史记录。
- S1-F1 的 Windows 公式重算调用已改为 sidecar 原生 COM（直接 `IDispatch`），不再通过 PowerShell 启动 Excel；GUI 与 CLI 批处理复用一个持久 Office COM 会话。每个工作簿的缓存清理、真实重算、完整结果校验和原子发布仍保留。预计收益包括移除旧 PowerShell 启动成本及批量场景下摊薄 Excel 冷启动；本次没有编译、运行或计时，收益尚未测量。
- S3-F1 在循环外预建日期、填色文本、数值和空白格式并按样式复用；全量逐项回读验证保留。因此原报告提出的“轻量化验证”没有实施，预计收益只来自格式对象复用，需复测。
- S2 目前不建议优化几十毫秒级差距，因为额外留痕有正确性价值。S5 配置审核按用户要求暂停开发，本次未修改 S5。
- 本文下方数字是 2026-10-29 修改前基线，不能代表本次代码性能。后续应以同版本样本、相同引擎、同一计时边界重新比较，并分别报告冷启动和批量热会话结果。

## S3-F1（Rust 1483ms vs Python 1114ms，差 ~370ms）

Rust CLI 分阶段实测（--developer-view，10k 行）：

| 阶段 | Rust 耗时 | 说明 |
| --- | --- | --- |
| 配置读取（3.0+3.1，calamine） | 34ms | |
| 本期/上期 CSV 读取（2×10k） | 248ms | |
| 八维配对+环比+规则计算 | **121ms** | 核心计算 Rust 远快于 Python |
| **结果工作簿写入+验证** | **1520ms** | 占 76%，差距全部在这里 |

写入阶段的两个实测成本点（`s3_execution_compare.rs`）：

1. **循环内每格新建 `Format::new()`**：10k 行 × 每行至少 1 个日期格式单元格
   （加带填色的单元格），每次都向 rust_xlsxwriter 的格式表注册新格式对象，
   拖慢保存并膨胀文件。**状态**：已按 2026-10-30 变更把日期、文本、数值及空白
   样式移到循环外预建复用；收益待复测。
2. **写后全量回读验证**：`validate_execution_compare_workbook` 用
   read_value_columns 独立读回 10k×22 全部单元格验证行列与表头。
   此验证保留，不为性能牺牲逐项结果检查。

另注意：旧 Python 的写出本身也调用 Rust 载荷写入器（`write_rust_payload`），
所以差距还包括 Rust 端的全量验证成本。验证继续保留，格式对象复用已实施；
剩余差距需要实测判断，不能按旧预估直接认定已经反超 Python。

## S1-F1 重算子步骤（Rust 6300ms vs Python 4658ms，差 ~1.6s）

实测分解（7,200 公式）：

| 成本项 | 实测 | 归属 |
| --- | --- | --- |
| Excel 实例创建+退出（冷） | ~4000ms | 两者都被 Excel 主导 |
| 打开+CalculateFull（进程内） | ~2200ms | 两者相同（同一 Excel 引擎） |
| **PowerShell 裸启动** | **295ms** | 仅 Rust 侧（COM 通道外壳） |
| **公式缓存清理（OOXML 重写 7,200 格）+ 结果校验 + 原子发布** | ~1000ms+ | 仅 Rust 侧（生产保障） |

Python 侧是裸 pywin32 重算（无缓存清理、无校验、无发布）——它少做的正是
Rust 多做的正确性工作。优化空间：

1. **批量模式**：2026-10-30 已在 GUI 和 CLI 使用持久 sidecar 会话复用同一个
   Excel/WPS COM 实例；批次工作簿顺序计算，冷启动开销可被摊薄。尚未复测。
2. **原生 COM 通道**：2026-10-30 已用 Rust 原生 `IDispatch` 替换公式重算路径的
   PowerShell COM 外壳。旧报告中的 295ms 是旧基线，不是新路径的实测成本。
3. 缓存清理、公式/缓存结果校验与原子发布是正确性保障，保留不裁剪。

## S5（Rust 57ms vs Python 23ms）与 S2（Rust 38ms vs Python 13ms）

差 25–34ms，分解：

- Rust CLI 进程启动：9.5ms（Python 计时不含解释器启动 39.5ms）。
- Rust 输出文件更多：审核副本（源+配置双拷贝）+ 审核结果 + 运行总账 JSON；
  S5 还含条件格式评估、结构快照、总账哈希。Python 对拍口径未做全部这些。
- 绝对差为几十毫秒级，真实批量（2026-10-27 真实 S2 批次 Python 服务阶段即
  839ms）下占比很低。**不建议为此优化**；若要省，可提供"轻量输出"开关
  （跳过配置副本拷贝），但会削弱留痕。

## 结论

| 功能 | 差距主因 | 可优化 | 预期收益 |
| --- | --- | --- | --- |
| S3-F1 | 写后全量回读验证 + 循环内格式对象 | 格式对象复用已实施；验证保留 | 未重新测量 |
| S1-F1 | PowerShell 外壳 + 冷启动 Excel 会话 | 原生 COM 与批量会话已实施 | 未重新测量；批次会摊薄 Excel 启动 |
| S5/S2 | 进程启动 + 附加留痕输出 | S2 不建议删减留痕；S5 暂停开发 | 几十毫秒（旧基线） |
