# S3-F2 进程树峰值工作集专测

## 结果

| 实现 | 峰值工作集：三轮中位数 | 三轮最大值 |
|---|---:|---:|
| Python 原实现 | 43.688 MB | 43.945 MB |
| Rust Release CLI | 44.340 MB | 44.383 MB |

本负载下 Rust 比 Python 多约 0.652 MB（约 1.5%），视为接近平价；没有足够证据为内存而改写 S3-F2。

## 负载与验证

- Windows 11 x86_64；Python 3.12.10；Rust 二进制 SHA-256：`a2ac5bc3fd16223a3c18976f9ed6042e941af6df17fc2fbd84ad5fe54b82f370`。
- 同一合成负载：1 份比较工作簿、1 张表、7,830 行数据、12 列；2,610 行入选；1 份 401 行机构映射工作簿。输入大小为 426,815 / 12,157 bytes。
- 每轮 Python 与 Rust 使用同一对输入文件，轮次交替先后；各启动全新进程。以 psutil 每 5 ms 采样进程树的 RSS/工作集总和，分别取每轮最大采样值，再报告三轮中位数和最大值。
- 三轮 Python/Rust 输出均逐格比较 2,610 行，0 差异；结果状态和行数符合预期。两个输入的 SHA-256 在所有轮次前后相同；进程树峰值进程数为 1。
- 本次只记录内存；不重报耗时倍率。原 S3-F2 7,830 行耗时和阶段基准保留在 `s3f2_scale_profile_20261030.json`。

## 限制与结论

工作集通过 5 ms 间隔采样，可能漏掉更短的瞬时峰值；计入新进程启动和 Python 导入成本，不包括输入生成或输出比较。三轮结果中 Rust/Python 峰值都稳定在约 44 MB，差值不足 1 MB，没有优先优化的内存瓶颈。测试使用合成文件，不代表真实机构工作簿的内存规模。
