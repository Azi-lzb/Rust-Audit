# S2-F1 配置读取与输出验证性能优化

日期：2026-10-30  
范围：Rust S2-F1；Windows 11；合成数据。旧 Python 项目只读参考。

## 优化内容

1. S2 配置检查与业务执行原先会分别读取同一配置工作簿，配置解析路径总计打开三次。现在配置检查和运行配置共享同一份 `SheetValues` 投影；公开配置检查仍保持原有报告接口。
2. S2 输出验证原先为了检查工作簿能否重开、工作表顺序和公式数，调用完整 `read_workbook`，读取所有值及附加元数据。现在通过 Calamine 读取工作表名称/顺序及公式范围，仅扫描验证所需信息；检查条件和临时文件发布顺序保持不变。

## 配置读取 A/B

五轮合成负载：1 本本期簿 + 1 本上期簿，728 个配置指标、7 个机构配置，输出 292 个单元格。

| 指标 | 修改前 | 修改后 | 变化 |
|---|---:|---:|---:|
| Rust 配置阶段中位数 | 40 ms | 15 ms | 减少 62.5% |
| Rust 服务总耗时中位数 | 64 ms | 38 ms | 减少 40.6% |
| Rust CLI 墙钟中位数 | 94.37 ms | 66.44 ms | 减少 29.6% |

Python 服务中位数分别为修改前 421.04 ms、修改后 397.29 ms；Python 源码未改，前后运行有自然波动，不把它视为优化结果。五轮 Rust/Python 摘要和 292 个输出单元格均逐项相同，输入哈希前后不变。

Python 服务计时不含解释器启动，Rust CLI 墙钟计入 CLI 启动，因此 Python/Rust 墙钟倍率仅作参考；Rust 自身前后比较使用同一 CLI 边界。

## 21+21 批量工作簿 A/B

合成负载：本期 21 册、上期 21 册，7 个机构、3 张报表、728 个指标；每期 5,083 条导入记录。保存阶段前后比较只改变输出工作簿验证路径，配置读取复用已在两边代码状态中生效。三轮交错测试：

| 指标 | 原验证路径 | 轻量验证路径 | 变化 |
|---|---:|---:|---:|
| Rust 保存阶段中位数 | 312 ms | 98 ms | 减少 68.6% |
| Rust 服务总耗时中位数 | 659 ms | 429 ms | 减少 34.9% |
| Rust CLI 墙钟中位数 | 738.45 ms | 500.95 ms | 减少 32.2% |
| Rust 进程峰值工作集 | 145,477,632 bytes | 107,913,216 bytes | 减少约 25.8% |

Python 服务中位数为 1,101.92/1,144.47 ms；Python 未修改。3/3 轮摘要与 81,372 个输出单元格逐项比较均为 0 差异，测量前后输入哈希不变。XLSX ZIP 容器字节数有少量差别；验证的是业务值/表结构，不宣称二进制文件相同。

跨语言倍率同样受 Python 服务计时与 Rust CLI 墙钟边界差异影响，重点比较相同 Rust CLI 前后的变化。

旧 Web 日志曾记录真实 21+21 批次总计 2,249 ms，但那是历史观察值，不是相同输入的 Python/Rust A/B；原始工作簿已不可用，不能用本合成基准代替真实数据复验。

## 结论

S2-F1 本轮找到两个有实测收益且保持业务输出一致的重复工作：配置工作簿多次读取和输出验证时整簿回读。两项已定点优化。S2-F1 总性能地图仍需继续补充真实文件规模、阶段计时与峰值内存；这些合成负载不构成完整迁移验收。
