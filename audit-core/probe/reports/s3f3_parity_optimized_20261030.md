# S3-F3 机构反馈导入性能与输出对拍（2026-10-30）

## 范围

沿用既有 1,000 条唯一反馈键、无冲突的合成负载。目标工作簿先复制到独立临时目录；Python 与 Rust 各处理 1,000 行，均须先生成与原目标字节一致的备份，再原地更新说明文件。输入共 2 个 XLSX：目标 47,165 bytes、1 张表 1002×8；反馈 50,080 bytes、1 张表 1001×8。反馈输入和基准目标在运行前后 SHA-256 未变。

使用 Release 二进制 SHA-256 `d21e355a8ec05129e81ccdda008f257a98702b64537010c24b773433b416db66`；预热一次后交错运行 3 轮。Python 计时不含解释器/模块导入，Rust CLI 墙钟含进程启动；两端计时均不含输出对拍。峰值工作集在独立进程运行中以 5 ms 采样，不含测试控制器。

优化前 / 优化后 Rust 内部总耗时中位数为 946 / 203 ms，减少 743 ms（78.54%）；CLI 墙钟中位数为 975.25 / 235.54 ms，减少 739.71 ms（75.85%）。Python 服务中位数从 977.03 变为 912.62 ms，属于分开批次运行的环境波动；性能结论以 Rust 同口径前后耗时和相同业务数据为主。

## 正确性和资源

每轮均导入 1000 条、未匹配 0、冲突 0；更新后的目标只改变 H3:H1002 的说明值，其它业务值和表结构保持不变。Python/Rust 输出逐格比较，包含公式文本与公式计数、工作表名/顺序/尺寸、合并区域、冻结窗格、筛选、隐藏行列及 data-only 读值，均为 0 差异。每份更新目标旁的备份与原目标 SHA-256 完全一致；反馈文件、源目标样本和 Python 源文件未变化。

独立进程树峰值工作集约 Python 38.86 MB（1 个进程）、Rust 21.73 MB（1 个进程）。采样值会漏掉短于 5 ms 的瞬时峰值，且 Python/Rust 启动边界不同；作为同机负载观察，不代表所有生产环境内存峰值。

## 判断

S3-F3 原地执行不再把临时 ExcelEditPlan 写为 JSON 后立即从磁盘读回，而是在同一计划验证与输入保护流程后直接把内存中的计划传给 Excel-Core。用户可见的“生成计划”命令仍保留 JSON 文件输出。完整输出和字节级备份检查均通过；本次优化减少了重复序列化/反序列化，不更改匹配、冲突、备份或原地发布规则。

本无冲突合成负载未覆盖冲突清单生成、真实业务大文件或 GUI 常驻服务，不能替代人工验收。

优化前逐轮数据见 [`s3f3_parity_profile_20261030.json`](s3f3_parity_profile_20261030.json)，本轮逐轮原始数据见同名 JSON，复跑驱动为 `tests/compare/perf_s3f3_parity_20261030.py`。本轮修改了 S3-F3 临时计划传递路径；Rust 业务匹配和输出契约保持不变。
