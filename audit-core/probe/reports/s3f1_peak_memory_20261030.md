# S3-F1 进程树峰值工作集专测

## 结果

| 实现 | 峰值工作集：三轮中位数 | 三轮最大值 | 峰值进程数 |
|---|---:|---:|---:|
| Python 参考实现 | 133.477 MB | 133.672 MB | 2 |
| Rust Release CLI | 119.035 MB | 119.098 MB | 1 |

10,000 行两期输入下，Rust 峰值工作集约低 10.8%（14.442 MB），属于温和差距。S3-F1 原有约 1.02×耗时结论保持不变；本轮只补峰值内存，没有重新测量或调整耗时基准，也没有代码优化建议。

## 负载、口径与正确性

- Windows 11 x86_64；Python 3.12.10；Rust 二进制 SHA-256：`a2ac5bc3fd16223a3c18976f9ed6042e941af6df17fc2fbd84ad5fe54b82f370`。
- 当前和上期 CSV 各 10,000 行、14 列，文件各 1,199,062 bytes；3.0 通用配置 4 张表、3.1 执行比较配置 5 张表。负载由既有 `perf_compare_20261030.py` 合成生成器产生。
- Python 和 Rust 分别在全新 worker 进程内运行三轮，执行先后交替；每 5 ms 对 worker 进程树累加 RSS/工作集。输入生成和输出对拍在被测进程之外，worker/CLI 启动成本计入峰值采样。
- 每轮比较一个输出工作表的 220,022 个单元格，工作表名、维度相同；值差异在 1e-10 容差外为 0，舍入到 10 位小数差异为 0，最大原始浮点差为 `2.117582368135751e-22`。公式数均为 0。输入 SHA-256 前后不变。
- 本轮不保存或比较执行时间，避免重做用户已结项的 S3-F1 耗时基准。

## 限制

5 ms 采样可能漏掉更短的瞬时峰值。Python 工作集包含解释器和其子进程；Rust 包含 Release CLI。该合成输入用于补齐内存维度，不代表真实 S3 配置或业务批次的内存增长曲线。
