# S1-F1 模板结构预检投影读取优化

日期：2026-10-30  
范围：S1-F1 模板结构预检读取；Windows 11；20,000 行合成工作簿。Python 20k 参考轮此前超过 150 CPU 秒未完成，本次不报告 Python/Rust 倍率。

## 变更

结构预检原先调用通用 `read_workbook`：把整本工作簿所有单元格转成 JSON/BTreeMap，并读取结构预检不使用的批注、条件格式和数据验证元数据。现新增 `read_workbook_structure_projection` 专用于结构匹配，只保留工作表目录、映射区域单元格值/公式和合并区域。Calamine 仍检查每张工作表的值读取，公式文本和值的类型语义与全量读取保持一致；源单元格若位于合并区域，会读取其左上锚点。

不支持错误值的现有兼容策略保持不变：投影读取遇到 Calamine 不支持的错误 token 时，调用现有 cell-scoped OOXML 临时规范化与 Calamine 重试，再从兼容结果提取投影。未把条件格式元数据带入此结构读取路径；S1 条件格式审核仍使用完整读取路径。

## 相同规模复测

使用原 20k Rust-only 尺度驱动、同一夹具生成逻辑、预热 1 轮和 3 轮计时。源/模板均为 1 张表、20,001 行（含表头）×8 列、160,008 个非空单元格、4 条条件格式规则；结构标签 8/8 匹配，扫描 80,000 个单元格，文件均为 716,663 bytes。前后运行 XLSX 容器 SHA-256 不同，因此不声称输入逐字节相同；工作簿维度、大小和生成器相同。每轮审核异常为 43,051 条，规范化异常 SHA-256 与旧状态三轮及新状态三轮完全相同；源/模板各自运行前后哈希不变。

| 阶段 | 优化前中位数 | 投影读取后 | 变化 |
|---|---:|---:|---:|
| 模板结构预检读取 | 528 ms | 224 ms | 减少 304 ms / 57.6%（约 2.36×） |
| 源读取 | 490 ms | 465 ms | 减少 25 ms；此路径不是本次修改目标，视为样本/缓存波动 |
| 条件格式计算 | 523 ms | 486 ms | 减少 37 ms；此路径未修改，视为样本/缓存波动 |
| 异常组装 | 314 ms | 318 ms | 增加 4 ms |
| 条件审核命令内部耗时 | 2,165 ms | 1,654 ms | 减少 511 ms / 23.6%；不可全归因于读取器 |
| CLI 墙钟 | 3,254.905 ms | 2,645.195 ms | 减少 609.710 ms / 18.7%；单机跨轮对照，不代表完整 GUI/COM 链路 |
| 峰值工作集 | 385.672 MiB | 385.824 MiB | 基本不变；峰值由后续条件审核全量读取主导 |

模板结构读取是此次明确受影响的阶段；CLI 与其他阶段变化包含工作集缓存和系统调度波动，故单独报告原始数值，不宣称这些阶段都由投影代码提速。

## 边界

该修改只减少结构预检阶段的临时对象和无关 OOXML 元数据解析；Calamine 仍需遍历读取各工作表值，所以不是按 XML 物理字节的随机访问。20k 全命令峰值内存没有下降，因为紧随其后的条件格式审核仍要完整读取值及条件格式规则。S1-F1 完整 GUI/公式复制/COM 重算/最终结果输出耗时仍未统一计量；本次也不构成 Python/Rust 20k 性能对比或真实机构样本验收。
