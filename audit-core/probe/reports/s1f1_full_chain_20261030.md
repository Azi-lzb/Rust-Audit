## 测量范围和输入

这次测量覆盖 S1-F1 从 GUI 接受的业务入口到审核结果工作簿输出，包括模板匹配和预检、条件格式审核、审核副本生成、外部引用表导入、公式复制及 Excel COM 重算、异常提取、结果汇总和写出。Python 通过只读参考项目的 `AuditService + run_dag_flow(dag:汇总核查表校验)` 执行；Rust 通过 Release CLI 的 `acceptance-run` 调用现有 GUI S1-F1 服务。正确性检查和额外的 Excel COM 打开检查在计时区间外运行。

夹具由 Python 参考流程生成，两个引擎使用同一批主输入；配置文件分别复制，避免历史说明回写互相影响。共 6 个输入工作簿、合计 37,755 bytes：

- 源文件 3 本、3 张 Sheet：1 本按结构拒绝，2 本进入审核。大小为 5,010、6,629、5,232 bytes，合计 33 个非空单元格。
- 模板 1 本、2 张 Sheet，36 个非空单元格，其中“审核规则”表 24 格。
- 外部数据 1 本、2 张 Sheet，4 个非空单元格；只复制公式引用的“参照表”，不复制“未引用表”。
- 配置 1 本、5 张 Sheet，64 个非空单元格。
- 预期审核结论：2 本通过结构审核、1 本跳过；2 条公式审核异常、1 条条件格式异常；最终结果 3 行。

逐轮业务耗时如下：

| 轮次 | 顺序 | Python | Rust | Python/Rust |
|---:|---|---:|---:|---:|

| 3 | Python-first | 7,132.25 ms | 6,890 ms | 1.035× |

本夹具上 Rust 业务步骤中位数约快 4.9%，但逐轮倍率从 0.884× 到 1.050×，应视为近似持平，不能据此声称普遍加速。worker/CLI 墙钟包含启动并持续计时到所有本轮新建 Excel 进程退出；Python 三轮为 34,469.29、32,747.97、10,983.02 ms，Rust 为 8,598.14、6,953.66、6,965.34 ms。Python 每轮观察到 2–3 个新 Excel PID，Rust 每轮 1 个；全部自然退出，没有被基准脚本强制终止，也没有遗留新进程。Python 的墙钟受 Excel 关闭/进程退出时间显著影响，故业务倍率使用流程内部计时，墙钟作为独立生命周期指标报告。冷启动后的 Excel COM 计算包含在业务计时内；单独用于“输出可打开”检查的 Excel 实例不计时。运行前已存在的 Excel PID 从内存采样中排除。

业务计时边界并非完全同构：Python 取 `run_dag_flow` 内部 `elapsed_ms`，Rust 取 acceptance adapter 的 S1-F01 步骤时间，其中有最多约 100 ms 的状态轮询粒度。Rust 进程墙钟另行记录，所以不把 worker/CLI 启动成本混进业务倍率。Rust 当前已在验收 JSON 暴露请求准备、模板匹配/预检、结构比较、Excel-Core 编辑、真实重算、公式/条件格式异常提取、结果写出及 Excel 会话关闭阶段。单轮分段测量说明见[阶段剖析](s1f1_stage_profile_20261030.md)。该分段轮与原干净三轮不是同一版本二进制，且当时有并发 Excel 负载，不能将新分段耗时回填到旧基准轮次，也不能把嵌套子阶段重复相加替代独立测得的总时长。原干净三轮的 Python 阶段日志已随原始 JSON 覆盖而不可恢复。

## 正确性证据

- 3 轮最终结果工作簿均为 52 个参与比较的单元格，行列尺寸一致，单元格差异为 0，均有 3 条结果记录。
- 两本审核副本的 D4/D5 公式文本与 Python 一致；重算缓存一致，并逐项符合独立预期值。
- 两本审核副本均包含“审核规则”表的 24 个内容单元格；表名、顺序、A1 批注文本和作者均与 Python 相同。未引用的外部表均不存在。Excel COM 保存重算结果会重写 Umya 导入批注的作者；现在在重算完成后、最终发布前，仅当批注位置和文本均与模板一致时，通过定点 OOXML Patch 恢复源批注 XML/VML，若内容不一致则失败关闭。
- Python 与 Rust 输出副本均由新建 Excel COM 实例逐本打开；每本有 3 张 Sheet，关键公式仍可读取；验证实例及业务新建 Excel 进程均正常退出，没有遗留的新 Excel 进程。
- 全部源文件、模板、外部簿及主配置的 SHA-256 在测量后不变；分开复制的历史配置也未被修改。

全链路对拍先发现 Rust 少复制“审核规则”表、整数审核说明显示 `10000.0` 的差异，随后又发现重算保存会把复制的规则表批注作者改成默认值。本轮补齐规则表复制/同名替换、整数显示和重算后的批注 XML/VML 定点恢复；测试拒绝批注位置或文本被改写的候选。三轮结果、公式缓存、批注作者与 Excel 打开检查均通过。这些是业务对齐修正，不计为纯性能收益。

## 结论和限制

在这套小型合成负载下，两边业务步骤基本持平，Rust 中位数约快 4.9%；Rust 进程树峰值工作集低约 40.7%。完整 worker 墙钟差距主要反映 Python 路径多次启动的 Excel 进程退出等待，不能等同于 Rust 业务计算快 4.7 倍。结果不能外推到真实机构大工作簿，也不证明 Linux/Kylin/UOS 性能。

样本规模小，进程内存每 5 ms 采样一次，可能遗漏更短时的峰值；不做普通字体、边框、样式逐项对比。S1-F1 的阶段分段已补齐，但目前只在一个合成输入上做了单轮诊断，仍不构成稳定的跨功能统一 profiler。定点测试 `s1_formula_copy` 17/17、OOXML 注释/VML 3/3 通过；Release 构建成功；未运行全 workspace 回归。工作区有未提交修改；没有提交或 push。
