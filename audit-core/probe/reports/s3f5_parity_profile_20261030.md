# S3-F5 金融表单性能与输出对拍（2026-10-30）

## 校正历史基准输入

首轮排查发现 `perf_compare_20261029.py` 与原 `perf_compare_20261030.py` 的 S3-F5 合成表单名为 `AF001`…`AF004`。业务类按表单工作表名中的 `A1/A2` 判定，因此这批输入未命中任何表单指标；本轮直接观测到 Rust `matched_indicators=0`、两端输出数值格为 0。旧报告只核对输出文件数量，故 2029/30 的 S3-F5 耗时不代表实际金融表单渲染，保留为历史记录但不作为性能基线。

已修复当前基准驱动 `perf_compare_20261030.py` 的配置生成器：表单名包含 `A1`，使人民币样例命中表单。专用驱动还强制检查匹配指标数和每轮数值单元格数量，避免再次出现空结果的假性能测试。没有修改产品业务代码。

## 有效负载与结果

Windows x64 使用既有 Release 文件 SHA-256 `9112415fb15454136905aefdd694236006178c177e6f542b0cb83e0215ac7ba4`。输入含 30 家机构、每家 40 个指标、4 张人民币 A1 表，共 1,200 条比较记录和 4,800 个表单指标行。工作簿大小：比较结果 76,926 bytes（1 张表、1,201 行、21 列）；3.0 通用配置 5,069 bytes（1 张表）；3.3 表单配置 9,337 bytes（6 张表，4 张表单各 41 行、7 列）。

预热一轮后，交错执行三轮。Python 时间包含服务启动 12 个 worker 以内的进程池并行渲染；Rust CLI 墙钟包含命令进程启动。

| 计时 | Python | Rust | Python / Rust |
|---|---:|---:|---:|
| 三轮中位数 | 3,509.17 ms | CLI 墙钟 1,538.36 ms | 2.28× |
| Rust 进程内服务计时 | — | 1,510 ms | 2.32× |

Rust 阶段中位数：输入读取 36 ms、规则规划 51 ms、逐机构编辑/写入 1,449 ms、总计 1,510 ms。每个输出的 Excel-Core 修改计时中位数 45 ms（最小 42、最大 55 ms），30 个输出依次写入。编辑写出占 Rust 运行绝大部分；现有 Rust 仍比 Python 快约 2.3×，本轮未发现值得承担并发写入复杂度的优化理由。

## 正确性与资源

- Python 与 Rust 每轮都生成 30 个同名机构工作簿。
- 每轮 30/30 本工作簿逐单元格比较；共 180 张输出表、35,460 个单元格、19,200 个数值格、5,160 行隐藏状态检查。比较单元格值、公式文本/缓存、工作表名称与顺序、维度、隐藏表/隐藏行及合并区域，三轮均为 0 差异。普通字体、边框和列宽不在本次正确性判定内。
- Rust 报告 1,200 条比较记录、30 家机构、4,800 个匹配表单指标、0 警告；原始比较表、3.0 和 3.3 配置哈希前后未变。
- 分开的进程树采样峰值工作集：Python 475.34 MB（峰值 13 个父/子进程），Rust CLI 24.25 MB（1 个进程）。采样间隔 5 ms，进程启动在内；这是 OS 工作集估计，不是目标服务器的完整内存压测。

逐轮机器数据见 [JSON](s3f5_parity_profile_20261030.json)，复跑入口见 [聚焦驱动](../../tests/compare/perf_s3f5_parity_20261030.py)。通用性能驱动的 S3-F5 输入生成器已经修正，后续运行也会产生实际表单回填样本。

## 决定

S3-F5 的有效负载已建立性能和全输出值级基准。Rust 的写出阶段仍是主要耗时，但总量约 1.45 秒且已快于 Python，故当前不改产品实现。若未来实际批次远大于 30 家机构，优先按逐机构编辑耗时复测后再决定是否并行化。
