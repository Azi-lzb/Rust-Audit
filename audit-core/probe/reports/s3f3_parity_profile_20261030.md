# S3-F3 机构反馈导入性能与输出对拍（2026-10-30）

## 范围

沿用既有 1,000 条唯一反馈键、无冲突的合成负载。目标工作簿先复制到独立临时目录；Python 与 Rust 各处理 1,000 行，均须先生成与原目标字节一致的备份，再原地更新说明文件。输入共 2 个 XLSX：目标 47,166 bytes、1 张表 1002×8；反馈 50,081 bytes、1 张表 1001×8。反馈输入和基准目标在运行前后 SHA-256 未变。

使用 Release 二进制 SHA-256 `9112415fb15454136905aefdd694236006178c177e6f542b0cb83e0215ac7ba4`；预热一次后交错运行 3 轮。Python 计时不含解释器/模块导入，Rust CLI 墙钟含进程启动；两端计时均不含输出对拍。峰值工作集在独立进程运行中以 5 ms 采样，不含测试控制器。

## 正确性和资源

每轮均导入 1000 条、未匹配 0、冲突 0；更新后的目标只改变 H3:H1002 的说明值，其它业务值和表结构保持不变。Python/Rust 输出逐格比较，包含公式文本与公式计数、工作表名/顺序/尺寸、合并区域、冻结窗格、筛选、隐藏行列及 data-only 读值，均为 0 差异。每份更新目标旁的备份与原目标 SHA-256 完全一致；反馈文件、源目标样本和 Python 源文件未变化。

独立进程树峰值工作集约 Python 38.66 MB（1 个进程）、Rust 20.70 MB（1 个进程）。采样值会漏掉短于 5 ms 的瞬时峰值，且 Python/Rust 启动边界不同；作为同机负载观察，不代表所有生产环境内存峰值。

## 判断

本样本 Python 服务与 Rust 内部耗时接近；Rust CLI 墙钟包含启动，因此整体 CLI 比较略慢。没有发现足以支持产品代码优化的明确热点；当前先保留原实现。该无冲突合成负载不覆盖冲突明细生成、真实业务大文件或 GUI 常驻服务，不能替代人工验收。
