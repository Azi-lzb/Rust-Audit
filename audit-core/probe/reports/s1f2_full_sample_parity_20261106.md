## 对齐结果

两端均成功处理 129 本源工作簿，无整本跳过；Rust 结构预检为通过 0、部分继续 129、跳过 0，缺少模板工作表的文件/工作表组合共 175 个。旧 Python 运行日志同样记录 129 次缺少“在线校验结果”和 46 次缺少“本地校验结果”，缺表时继续处理可用工作表。

修复前，两端非空数据行和值完全一致，但工作表顺序、四个报送元数据列顺序不同。原因是 Python 按“工作簿级定义名称优先、再按工作表顺序读取工作表级定义名称”，Rust 原先采用 OOXML 原始顺序并按单元格位置排序字段。Rust 现在复现 Python 的定义名称与字段顺序，输出工作表按旧版顺序写入。

修复后，工作表顺序、表头及全部非空单元格位置和值完全相同；按单元格类型归一化比较，无 Python-only 或 Rust-only 行，也无位置差异：

## 需业务确认的数据/模板差异

源文件中有 28 本包含名为“在线抽验结果”的工作表；当前旧版模板定义的是“在线校验结果”。因此旧 Python 和 Rust 都按模板定义生成空的“在线校验结果”表，并没有把这 28 本的“在线抽验结果”内容纳入汇总。测试目录原有 `汇总信息.xlsx` 则含“在线抽验结果”表（工作表尺寸 123×15），且工作表集合与本次按旧版 GUI 新生成的输出不同。

业务方已确认这是当前模板定义的问题，后续会自行修改模板。本次迁移按模板定义输出，空的“在线校验结果”与旧 Python 一致，因此 S1-F02 当前模板口径下的新旧同步已确认；不新增“在线抽验结果”到“在线校验结果”的代码映射。根目录已有 `汇总信息.xlsx` 是既有结果，其表名与本次旧版 GUI 按当前模板生成的输出不同，不作为本次迁移对齐标准。模板后续修改后，如需纳入“在线抽验结果”，再使用新模板重新运行并核验。
