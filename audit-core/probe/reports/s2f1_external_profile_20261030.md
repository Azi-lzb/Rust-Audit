# S2-F1 外部核对性能剖析（2026-10-30）

## 范围和计时口径

对照 Python 原 `PeriodAuditV2Service` 与已存在的 Windows Release CLI。复用 `manual_acceptance/20261027/s2_f01_external_rule_cases` 隔离副本，分别运行正常外部值和异常外部值；每种情形预热一次，再交错跑三轮。输出均写到临时目录，原样本只读。Python 计时为已导入服务后的业务调用；Rust 同时记录 CLI 墙钟（含进程启动）和 CLI 进度事件的服务阶段时长。

Release 文件 SHA-256：`9112415fb15454136905aefdd694236006178c177e6f542b0cb83e0215ac7ba4`。

## 结果

| 外部核对情形 | Python 服务中位数 | Rust CLI 墙钟中位数 | Rust 服务阶段中位数 | Python / Rust CLI | Python / Rust 服务 |
|---|---:|---:|---:|---:|---:|
| 正常：1,234,567.89 对 1,234,567.89 | 41.92 ms | 50.26 ms | 24 ms | 0.83× | 1.75× |
| 异常：1,234,567.89 对 1,234.50 | 42.19 ms | 51.56 ms | 24 ms | 0.82× | 1.76× |

CLI 墙钟包含约 26–28 ms 的启动和命令行开销。S2 Web/GUI 调用常驻进程内服务时，这部分不在每次业务调用路径里；这组小样本的服务本身 Rust 用时更短。没有据此修改业务实现。

## 阶段中位数

| 阶段 | Python 正常 / 异常 | Rust 正常 / 异常 |
|---|---:|---:|
| 配置检查与读取 | 29.46 / 29.36 ms | 3 / 3 ms |
| 本期读取 | 1.23 / 1.37 ms | 1 / 1 ms |
| 上期读取 | 1.08 / 1.42 ms | 1 / 1 ms |
| 外部工作簿读取 | 3.18 / 3.80 ms | 1 / 1 ms |
| 环比及规则计算、外部比对 | 各低于 0.2 ms | 各 0–1 ms（事件时钟取整） |
| 报告写出 | 1.99 / 2.32 ms | 2 / 2 ms |
| 保存、回读验证及发布 | 3.79 / 3.92 ms | 15 / 15 ms |

进度事件以毫秒整数记录，亚毫秒阶段显示为 0 或 1；阶段边界按不同阶段首次事件的服务内时间差估算，不应将各阶段四舍五入值相加后当作精确总时长。Rust 的保存/回读阶段较 Python 长约 11 ms，但整个 Rust 服务仍较短，当前输出也更大（正常样本约 9.2 KB 对 7.2 KB）；小样本不足以证明值得降低验证强度或重写 writer。

## 数据和正确性

- 两份源报表各 6,033 bytes，每份 2 张表、20 行（含表头）；本期及上期分别读取一份。
- 配置 8,656 bytes、6 张表；外部数据 6,164 bytes（正常）或 6,161 bytes（异常），各 3 张表。
- 输出 3 张审核表，共比较 292 个单元格。每种外部数据 3/3 轮摘要一致，工作簿值、公式、样式、尺寸和所测结构属性比较无差异。
- 每轮另核对指标 `20202001`：正常情形外部值 1,234,567.89、差值 0；异常情形外部值 1,234.50、差值 1,233,333.39、级别“硬性”。
- 原始输入副本 SHA-256 前后不变。Python 源码相关文件 SHA-256 前后不变。
- 每本输出有 4 个校验详情路径字符串仅因 Rust 使用 Windows `\\?\` 扩展路径前缀而不同；去掉该前缀后内容相等。除这项路径表示差异外，每轮工作簿差异数为 0。
- 单独进程采样的 OS 峰值工作集（包含各自进程启动）：Python 40.69 MB，Rust CLI 13.09 MB（正常）；Python 40.71 MB，Rust CLI 12.38 MB（异常）。该小样本只反映进程峰值，不等于完整批处理峰值或峰值 RSS 统一基准。

原始逐轮、阶段、输入规模、哈希、峰值内存数据见 [JSON](s2f1_external_profile_20261030.json)，复跑入口为 [perf_s2f1_external_20261030.py](../../tests/compare/perf_s2f1_external_20261030.py)。

## 决策

当前没有高收益的 S2-F1 微优化目标：服务内 Rust 阶段较快，独立 CLI 的小幅慢差主要来自命令启动；保存验证虽有可见阶段差，但 15 ms 总量且现有验证应保留。下一步优先检查较大 S3-F5 业务样本输出值级正确性和阶段数据，不进行 S2 业务重构。
