# S1-F1 条件格式指标定位性能优化

## 测量范围

本专项测量 S1-F1 的模板结构预检与条件格式异常提取，不含模板目录匹配、复制外部表、公式重算、公式异常提取和最终审核结果工作簿写出。

Windows x64 使用 Python 3.12.10 与 Rust Release CLI。每轮使用同一份生成的源/模板 XLSX：1 个工作表、4,000 行数据（含表头共 4,001 行）、8 列、32,008 个非空单元格、4 条条件格式规则；扫描 16,000 个格并形成 8,610 条异常。模板结构区域为 `S1Conditional!A1:H1`。预热 1 次后交错运行 5 轮，分别保留优化前后逐轮机器数据。每轮源文件和模板文件的 SHA-256 均前后一致。

优化前和优化后容器大小分别为 144,031 与 144,030 字节；两份样本由同一确定值生成器生成，只有 XLSX 容器字节存在 1 字节差异。每个 A/B 轮次中 Python 与 Rust 使用同一对输入。

## 瓶颈与修改

Rust 原指标解析器对每条触发异常都从结构起始行重新扫描至触发行，累积该列全部有序去重文本。每次查找都重复访问相同单元格，导致异常组装随行数呈二次增长。优化前 Rust `issue_build` 中位数为 15,523 ms；Python 旧流程也重复执行相同的逐异常前缀扫描。

现在 Rust 按工作表和目标列归组触发位置，按行单次累积列前缀标签，再在原触发位置组装异常。左侧行标签仍逐触发格读取；合并单元格锚点、文本过滤、数字排除、顺序去重、标签拼接和输出顺序保持原有语义。没有更改条件格式规则或 Python 项目。

## 性能结果

| 指标 | 优化前 Rust | 优化后 Rust | 变化 |
|---|---:|---:|---:|
| 指标/异常组装中位数 | 15,523 ms | 57 ms | 约 272.3×，耗时减少 99.63% |
| 结构预检 + 条件格式 Rust developer event 耗时（不含进程启动） | 16,044 ms | 498 ms | 约 32.2×，耗时减少 96.90% |
| Python 结构预检 + 条件格式中位数 | 20,859.4 ms | 19,264.7 ms | Python 未修改；两轮新生成 XLSX，读数波动不作优化前后收益 |
| 优化后 Python / Rust 内部阶段计时 | — | 19,264.7 / 498 ms | 38.68×参考值；两侧均不计外层进程启动 |
| Rust 采样峰值工作集 | 86.61 MB | 86.56 MB | 基本不变 |

优化后 Rust 各阶段中位数为：模板读取 95 ms、结构预检读取 99 ms、条件格式读取 97 ms、条件格式求值 88 ms、异常组装 57 ms。完整业务事件耗时中位数为 498 ms；该计时从命令处理开始，不包含外层 CLI 进程创建。阶段中位数来自独立事件，不应简单相加代替总事件耗时。

优化前异常组装占据总耗时绝大部分；优化后读表与求值成为主要已测成本。结构预检和条件审核当时分别读取同一源工作簿，样本中合计约 196 ms；后续已合并为单次源读取，结果见 [源读取复用优化报告](s1_source_read_reuse_optimization_20261030.md)。源投影仍不跨公式副本和 COM 重算阶段保留。

## 正确性与验证

- 优化前后各五轮都生成 8,610 条异常。优化后每轮 Python/Rust 规范化异常字段 SHA-256 多重集一致，缺失和额外记录均为 0。
- 五轮结构预检均匹配 8/8 个结构标签；源文件和模板哈希在每轮执行前后保持相同。
- Rust 库定向测试：`cargo test -p audit-core --lib s1_conditional_audit::tests -- --nocapture`，5 passed / 0 failed。新增用例覆盖乱序目标、重复位置、有序去重、合并单元格锚点，并与原逐个解析语义对照。
- Release 构建：`cargo build -p audit-core --bin open-data-audit --release`，成功。构建输出包含仓库中既有弃用 API 和未使用代码警告；本次修改没有新增告警。
- 没有运行全 workspace 回归、真实机构工作簿 GUI 验收或 Linux/Kylin/UOS 验收。
