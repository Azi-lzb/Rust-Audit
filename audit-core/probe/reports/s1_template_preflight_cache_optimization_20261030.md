# S1-F1 模板预检复用与读取规模剖析

日期：2026-10-30  
范围：S1-F1；Windows 11；Rust 合成样本。旧 Python 项目只读参考。

## 确认的重复工作与修改

`run_s1_f1_worker` 原先对每个源文件逐个调用模板推荐及 `s1_f1_template_preflight`。同一模板用于多个源文件时，会反复读取该模板的公式规则、条件/结构映射、定义名称、工作表目录和结构区域。现在在单次 GUI 批次内以 canonical 模板路径缓存完整预检计划，并由 `Arc` 让通过预检的文件共享同一只读计划；成功和失败结果都只针对本次批次缓存。

模板路径不同仍分别检查；每个源工作簿仍单独做结构匹配。模板或映射文件不会写入，源文件不变。S1-F3 恢复路径依然独立创建当次预检，不跨审核批次复用缓存。

## 读取规模剖析

20,000 行 Rust-only 合成样本：1 张表、8 列、160,008 个非空格、4 条条件格式规则、80,000 个扫描格，源与模板各 716,663 bytes；预热 1 轮、计时 3 轮。当前 Release SHA-256：`6fdff754c20b2da32946a9b957772c0fcbb4a356f4a2e451be745876140768ff`。

| Rust 阶段 | 中位数 |
|---|---:|
| 源工作簿读取 | 490 ms |
| 单次模板预检读取 | 528 ms |
| 条件格式计算 | 523 ms |
| 异常组装 | 314 ms |
| 条件审核命令内部耗时 | 2,165 ms |
| CLI 墙钟 | 3,254.905 ms |
| 峰值工作集 | 385.7 MiB |

三轮结构标签均 8/8 匹配，每轮异常均为 43,051 条且摘要 SHA-256 完全一致；源和模板 SHA-256 前后未变。阶段计时存在包含关系，不能相加等于 CLI 墙钟。

缓存前每个同模板源文件都会触发一次 528 ms 模板预检读取。在该合成工作簿的规模下，3 个源文件共用一个模板预计减少约 1.06 秒预检读取，21 个文件预计减少约 10.56 秒；这是按单次模板读取成本乘以避免的重复次数推算的，不是完整 GUI 批次 A/B 实测。

## 验证

- 缓存单测断言相同路径返回同一个不可变 `Arc` 计划并只存一个条目：1/1 通过。
- 现有 S1-F1 两文件混合重算模拟：1/1 通过。
- 现有条件审核失败时保留公式发现的测试：1/1 通过。
- Windows 三文件 GUI 合成流程：3/3 通过模板与结构预检，源/模板哈希未变；本机 Office COM worker 未能启动，LibreOffice 不可用，业务路径正确保留 3 本待人工重算副本，未发布虚假的完成结果。这个结果验证的是 GUI 接线与能力降级，不是公式重算成功验收。
- 20,000 行 Python 参考路径在超过 150 CPU 秒仍未完成；已停止该超大双端运行。故 20k 只作 Rust 尺度/重复性剖析，不声称 Python/Rust 等价或速度倍率。4,000 行跨引擎条件/结构 A/B 仍以既有五轮报告为准。
- Release 构建成功；剖析驱动 `py_compile` 通过。未运行全 workspace 回归、真实机构文件人工验收或 Linux/Kylin/UOS 验证。

## 未解决候选

当前 20k 样本仍需分别读取每个源文件（490 ms）和每个不同模板（528 ms）；这轮只消除了同批次同模板的重复读取，没有开发定点区域读取器。旧脱敏真实结构样本曾记录 Rust 源读取 983 ms、Python 77 ms，但旧文件不可复测。是否继续优化读取器，应先用同规模、获准的脱敏业务文件或可验证的合成工作簿复测，并保持条件格式实际触发结果一致。
