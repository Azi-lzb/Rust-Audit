# S1-F1 条件格式异常提取性能剖析

## 测量范围

本报告覆盖 S1-F1 的条件格式审核子步骤，不包含模板匹配、结构预检、模板/外部表复制、公式重算、公式异常提取或最终结果工作簿写出。该专项不重复 S1-F1 COM 批量重算测试。

使用同一生成的 XLSX：1 张工作表、4,000 行数据、8 列、32,008 个非空单元格、4 条受支持条件格式规则，文件大小 144,034 字节。规则扫描 16,000 个单元格，形成 8,610 条异常。Windows Python 3.12.10；Rust 使用既有 Release CLI，SHA-256 为 `74c167b5a304d357bfd14f4dab3f65f173c63e8c45a0b631bf7323891148edef`。

先预热 1 次，再按交错顺序各运行 5 次。Python 取 `ConditionalFormatService` 服务内部计时，Rust 取 `conditional-audit` 内部进度事件计时；均不含结果 JSON 序列化和进程启动。峰值工作集在独立 Python/Rust 子进程中由父进程每约 5 ms 采样。外部子进程墙钟受 Python worker 的 JSON 输出和启动开销影响，不用于计算加速比。

## 结果

| 指标 | Python | Rust |
|---|---:|---:|
| 服务内部中位数 | 1,343 ms | 246 ms |
| 最小–最大 | 1,312–1,516 ms | 229–270 ms |
| Python/Rust | — | **5.46×** |
| 规则读取/规范化 | 读取字段报告 0 ms；规范化 62 ms | 读取 102 ms |
| 规则求值 | 844 ms | 94 ms |
| 异常组装 | 453 ms | 24 ms |
| 峰值工作集 | 87.94 MB | 85.53 MB |

在这个 8,610 条异常的合成负载中，Python/Rust 的主要差距在规则求值和异常组装；Rust 读取约 102 ms。该结论不代表小负载或生产文件。此前一份真实工作簿的单次记录为 366 个扫描格、348 条异常，Python 375 ms、Rust 618 ms，其中 Rust 读取阶段 578 ms；该原始输入路径、字节大小和工作表数未留存，也没有重复轮次，无法与本次合成数据做同输入复测。两组数据说明 Rust 读取成本可能在小型审核负载中占主导，但尚不足以据此定点更换读取路径。本轮不改业务实现，保留真实单次数据作为待复现的风险点。

源码路径还显示，启用结构预检时，S1-F1 先通过结构比较读取输入工作簿，之后条件格式评估再次读取；中间包含公式副本处理和重算。本次单项对拍不包含这段完整流程，未测重复解析的端到端成本，也未测试为了复用整簿投影而增加的批量内存占用。将该项列为后续剖析候选，不直接改变业务调用顺序。

## 正确性

- 五轮每轮均得到 8,610 条异常。
- 每轮 issue ID、位置、数值、说明及其他异常字段逐项一致；缺失、额外和字段差异均为 0。
- 两端均支持 4/4 条规则，诊断为 0。
- 工作簿运行前后 SHA-256 一致。
