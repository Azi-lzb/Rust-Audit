## 新基准记录要求

1. 每次只运行明确授权或目标要求的单项功能；先检查历史台账，避免重跑已完成的 S1-F1、S3-F1 基准。
2. 输入必须相同并记录文件数、字节数、工作簿/Sheet/行列、公式量、输出规模、操作系统和 Release 二进制 SHA-256。
3. 保留逐轮原始数据；三轮或以上时报告中位数及 Python/Rust 倍率。标明 Python 计时边界、Rust CLI/worker 启动边界和外部 Office 冷启动是否包含。
4. 如有阶段计时，避免重叠区间相加；端到端计时必须独立测量。尽可能记录峰值进程内存和 Excel/LibreOffice 实例数。
5. 计时与正确性分开记录。比较输出值、公式及缓存、关键工作簿结构和输入保护；未做的项标为未验证，不以成功写出替代对拍。
6. 优化前保留基线，优化后仅复用同一业务数据及相同计时边界；同步追加 `PERFORMANCE_HISTORY.md` 和变更记录，并记录对应 HEAD/源码提交（若已获授权提交）。不要覆盖旧报告。
7. 仅当绝对耗时、使用规模及阶段证据共同支持收益时才实施优化；小负载倍率差不能单独成为重构理由。

S1-F1 全链路及 S1-F2 对拍报告以独占创建方式保存；指定的报告路径若已存在，驱动会拒绝覆盖。S1-F1 自动文件名包含 UTC 微秒，减少并发或快速复跑时的重名风险。

S1-F1 条件格式子步骤、S3-F2 放大规模、S3-F3 优化前后、S2-F1 外部规则及 S3-F4/F5 专项均使用专用驱动；其它条目按各自历史证据标明边界。S3-F3 定向测试与 Release 构建结果见性能历史及迁移清单；没有运行全工作区回归。
