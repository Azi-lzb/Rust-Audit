## 3. 通用要求

1. 输入原始报表始终保留，不允许审核流程覆盖源文件。需要修改公式的 S1-F1 使用**独立审核副本**。
2. 默认配置及最近使用路径沿用旧版机制；用户明确选择的输入优先。输出路径默认在本期/源文件所在位置创建 `执行结果`，具体文件层级、命名与旧版本对齐。
3. 批量运行必须记录各文件状态：模板匹配失败、结构异常、取数失败、计算失败、业务异常、成功且无异常，不可混淆。
4. 机构、报表、日期、代码、维度和单位必须基于真实配置与旧版逻辑处理；不臆造映射或统一容差。
5. 对完整的旧版输出协议，以旧程序真实执行结果为黄金样本。记录异常明细差异，而不是只说结果“数量接近”。
6. 优先使用本项目 Excel-Core：Read `calamine`；Create `rust_xlsxwriter`；Edit 按实际能力选用现有 OOXML Patch/`umya-spreadsheet` 等；外部公式计算由显式选择且已验证的 sidecar 能力提供。**S2、S3 不应为了规则求值调用 Office 引擎。**
7. 实现后先静态检查并交付用户人工构建与验收；Agent 编译、运行 Rust 测试或打包须获得用户对相应操作的明确授权。按实际需要集中验证 Windows、麒麟/UOS 和离线部署，未运行的项目不得标为通过。

## 4. S1：逐笔统计系统（保留旧模板审核链路）

### 4.1 S1-F1 汇总核查表校验【已确认】

**输入与 GUI**
- 批量选择源文件；选择外部文件、模板文件目录；默认配置已设定。
- 默认在源文件目录附近新建 `执行结果` 作为输出目录。
- 点击「自动识别模板」后可以人工检查，也可以不检查；再点击「F1 汇总核查表校验」。

**执行链路**
1. 自动匹配源文件与模板，报告匹配情况。
2. 使用模板的 `表结构区域` 比对源文件结构；不匹配的源文件**跳过，不继续生成误导性的审核结果**。
3. 在源文件独立副本中复制模板 `校验区域`，保留公式、必要格式、引用和平移语义；不修改原始源文件。
   模板中“校验区域”外的数字、文本和公式可能是人工测试规则时临时修改的内容，不复制、不提取为审核公式，也不作为复制阶段的公式一致性门槛。表结构/表头检查独立执行。条件格式值默认从原始源核查表读取；高级设置可改为从复制校验区域并重算后的审核副本读取，以支持未来校验区域落入数值区域的模板。S1-F3 人工重算恢复沿用启动 S1-F1 时保存的来源选择。
   外部辅助工作表含公式时必须进入支持公式的导入能力，保留原坐标及其依赖工作表，不能仅因纯数据 OOXML 快速路径不支持公式就停止整条链路。用户确认旧 Python 采用 OOXML 优先、遇公式回退 openpyxl；Rust 保留已有支持公式的 Excel-Core 路由，不把公式转成缓存常量。
4. 使用 Excel/LibreOffice **强制重算并保存副本**，读取真实公式计算结果，不能只信任 Rust 内存计算或旧缓存。尤其注意 `INDIRECT`、动态引用、外链和易失函数。
5. 从校验区域提取包含「错」「硬性」「软性」等业务关键词的结果，保留单元格**完整的计算结果文本**。
6. 处理数字单元格的**条件格式触发**，不是简单把所有条件格式规则当作异常，也不是仅凭静态填充色判断。优先 Rust 本地按旧 Python 行为求值；记录触发单元格的批注、条件格式公式和实际值。
7. **两类异常合并到同一张审核明细表**，输出格式、工作表、列名/列序、报表文件名及运行日志一律与旧 OpenDataAudit 的实际输出对齐。
8. 保存带公式且已重算的审核副本；计算失败、外链失败和结构跳过须清楚报告，不作为审核通过。

**技术和验收边界**
- 计算后端：Windows Excel COM / Linux LibreOffice（按平台可用性与既有接口）。LibreOffice 与 Excel 公式兼容差异需用真实文件核验。
- 条件格式：Rust 求值需要处理相对/绝对引用、规则适用区域、优先级与实际触发；不支持的规则必须明确报告。
- 旧版曾有不同环境审核条数差异，**不能用“量级一致”代替逐条业务差异核对**。
- 模板匹配优先级、复制目标和偏移、关键词全集、结果具体列与输出样式、外部文件添加行为：**旧版对齐**。

### 4.2 S1-F2 汇总校验结果说明【已确认】

- 面向机构提交的校验结果说明文件：模板识别 → 表结构比对（不合则跳过）→ 任意行区域汇总 → 历史审核结果关联 → 输出。
- 不同机构允许有不同明细行数；按模板指定列，向下动态读取实际有效行，跳过整行所选数据列均为空的行，不固定终止行。
- 从既有历史审核结果配置读取历史记录，按旧版业务关联键关联本期行，并附加历史触发条数、历史分类说明、审核结果等字段。
- **不覆盖已有历史配置**；历史富化不意味着本期自动审核通过。
- 结果 Sheet、列顺序、格式及关联键均以旧 OpenDataAudit 输出及 `region_summary` / `history` 等对应实现为准。
- 一般不需要 Office 公式重算。

### 4.3 S1-F3、F4、F5【暂缓】

- 组合工作表（核查表）、组合工作表（按配置）、制作联合模板均为预留功能，本轮不实施，不为它们预先开发专用架构。

## 5. S2：报表采集系统

### 5.1 S2-F1 报表采集审核【已确认】

**输入**：选择本期、上期、外部数据文件；报表采集配置有默认路径，输出默认在本期待处理目录新建 `执行结果`。旧版配置为 `2.报表采集系统_配置.xlsx`（用户提供过版本文件），实际报送数据可能为 `.xls`。

**标准化与取数**
- 从文件名和数据内容识别机构、报表代码、数据期、指标等，依据 `机构参照`、`指标参照` 等配置映射。
- 支持真实源报表格式；机构代码与统一社会信用代码保持文本语义，不能丢失前导零或精度。
- `通用设置` 管理源数据单位、外部文件单位、输出单位、指标输出/隐藏等选项；数值归一、单位换算只作用于配置规定的数据属性。

**必须实现三种规则**
1. **环比比较**：按机构与指标关联本期、上期，根据配置的环比策略及值域判断触发；包含缺失值、零值、文字变化等旧版语义。
2. **外部核对**：按配置寻找本期与外部指标，执行各规则的比较方式、独立容差与级别，不硬编码统一容差。
3. **校验规则**：Rust 受控表达式求值，根据启用状态、指标引用、规则级别生成结果；不依赖 Excel/LO 计算公式。

**输出**：直接对齐旧版《报表审核清单》，保留完整指标记录及按配置隐藏正常行等设置，不仅输出异常行。具体列名、样式、公式/文字口径及文件配对细节以旧版对齐。

- `V_CUR` 从本期源文件按工作表、行头路径、列头路径交叉定位；`V_PRE` 从可选上期文件按同一机构代码匹配后读取。选择上期文件时必须填写早于本期的报告期；身份无法识别、没有匹配文件或匹配到多份时须明确报告，不能默默返回空/0。
- GUI 允许绑定一个大集中外部工作簿；现有 CLI 多来源绑定能力继续保留。若 GUI 业务配置引用多个逻辑外部来源，必须明确提示改用 CLI 多来源绑定或拆分配置。

### 8.2 模板与结构比对【已确认】

- 模板用于自动识别、**表结构比对**和行列路径参照，不承担公式审核计算。
- 必须执行表结构比较并提示差异；**允许行列位置变化**。
- 行列移动后，若通过配置路径仍能唯一、可靠定位，**继续审核，同时提示位置变化**。
- 缺失路径、重复命中、路径歧义、关键结构无法判断时明确报告，不能猜位置或当作审核通过。
- 对受影响的规则/Sheet 按安全边界跳过；不应因局部结构变化自动跳过一整个本可正常审核的文件。

### 8.3 规则取数与执行【已确认】

- 读取已配置的业务名称、工作表名称、规则编号、校验类型、级别、取值字典、审核表达式、布尔值取反、描述、当前值/对比值/差值表达式等实际字段。
- 按配置执行类似 `V_CUR("工作表", "行头层级路径", "列头路径")` 的动态取数。
- 正确支持实际启用规则用到的数值、比较、逻辑、空值、函数等表达式语义；采用受控 Rust 求值器，不执行任意脚本。
- 明确区分**未触发、触发、取数失败、表达式执行失败**。
- 输入来源预检与规则执行共用本报告期的有效修订选择，显式 `source=` 优先；过期规则不得额外要求未使用的输入。保留旧版对模板校验区域公式的字面错误、源文件已有缓存错误、缺少工作表及扫描失败的只读诊断；该诊断不执行公式计算。
- `布尔值取反` 的确切触发语义、Excel 双精度/空白值等边界按照现有规则约定与真实测试确认，不凭直觉倒置判断。
- 先跑通少量不同类型的真实规则，再扩展覆盖现有全部启用规则；输出不能以“规则读取成功”代替“规则执行完成”。

### 8.4 条件格式审核【已确认的方向，具体兼容待验证】

- 对 `.xlsx` 源文件优先通过 OOXML `conditionalFormatting`/`sqref`/`cfRule` 获取规则及适用单元格，**不强制依靠独立的数字区域命名区域来限定扫描**。
- OOXML 只定义规则和应用区域，不能直接提供“已触发单元格”；需要 Rust 结合实际值、引用偏移和规则语义求值。
- 模板存在“条件格式区域”时按其范围扫描源工作簿规则；模板未定义该范围时回退到源规则的 AppliesTo，不强制补建命名区域。
- 触发异常提取批注、规则公式和数值等旧版需要的信息。
- 不支持的条件格式类型或旧 `.xls` 路径明确报告并采用经验证的兼容方案，不能悄悄忽略。

### 8.5 S5 结果协议【已确认】

沿用上传配置中的 13 列：

2. 工作表名
3. 定位单元格
4. 错误类型
5. 校验类型
6. 校验指标
7. 描述
8. 当前值
9. 对比值
10. 差值
11. 规则编号
12. 历史校验说明
13. 审核意见

优先对齐配置中 `核查表校验结果` Sheet 的现有样式和字段；结构差异/运行问题可在日志中补充，不任意混入业务异常。

多文件批次须保留结果所属工作簿、逐文件执行状态、每个物理来源的独立哈希及不覆盖的审核副本。GUI 批次逐机构比较结构快照并保留机构上下文，不将最后一家机构的布局写成共享基线。
