## 实施内容

- `native_office_com.rs` 增加 Excel/COM 初始化与每个属性设置的分段计时，明确记录 COM apartment 清理、应用退出及 Office 进程身份。加入精确进程句柄的存活确认。
- `native_recalculation.rs` 将 worker 关闭改为显式 Excel `Quit`、释放 COM、`CoUninitialize`、发送关闭完成消息并正常返回；不再通过 `process::exit` 跳过 Drop/COM 清理。Debug 测试可注入成功计算后的延迟响应。
- `s1_recalculation.rs` 在批次 worker 收到关闭确认后等待 worker 和具备 PID+创建时间校验的 Excel 进程退出；异常或超时只清理本 session 所有的进程。新增显式 executable 构造入口供集成测试使用。
- `s1_native_com_session.rs` 覆盖真实 COM 两册复用、源文件保护、正常 Quit/Excel 退出，以及超过 35 秒的 parent timeout 清理。
- 新增合成 A/B harness `tests/compare/s1f1_final_acceptance_20261030.py`：两端同负载，2/10/33 册批量、故障后继续、公式缓存/哈希、输入保护、PID 所有权和退出检查。
- 将 `DEVELOPMENT_GOAL.md`、`MIGRATION_INVENTORY.md` 中字面量 `\n` 文本恢复成实际 Markdown 换行；保留历史内容并新增本轮状态和证据链接。

## 验收结果

- A/B 每批中位数（Python / Rust）：2 册 7,570.60 / 7,171.91 ms；10 册 12,246.33 / 12,139.69 ms；33 册 27,006.11 / 27,138.94 ms。Rust 在 2/10 册快约 5.27% / 0.87%，33 册慢约 0.49%；方向随批次规模变化，判定为平价。
- Excel `DispatchEx` / `CoCreateInstance` 激活中位数 2,524 / 2,391 ms；新建进程后 COM ready 估算约 2.503 / 2.384 秒。Rust worker `spawn` 6.23 ms、ready IPC/启动残差约 37 ms。两边都以独立 Excel PID 执行。
- 完整关闭等待 Excel 进程真正退出约 2.74 秒。此前约 0.2 秒只表示 COM 代理释放，不能当作 Excel 已退出。新端到端计时统一包含进程退出等待。
- 9 批/引擎各输出 96 册，每册验证 6,000 个公式、7,200 个非空缓存；每引擎共核验 576,000 个公式结果和 691,200 个缓存项。96 对 Python/Rust 公式和结果哈希全部一致；输入哈希不变。
- 2 册规模中每引擎注入 1 个损坏工作簿，记录失败后继续处理后续有效文件；无跳过。每批只创建一个专用 Excel，15 个基线 Excel PID 保留，18 个批次自有 Excel/worker 全部退出、无强制终止。报告快照中还有未归属给本 harness 的短暂隐藏 Excel COM 进程；随后自行退出，未被本轮终止。
- 正常 COM 集成测试 1/1 通过；受控 parent-timeout 集成测试 1/1 通过。timeout 模拟重算成功后 worker 响应被延迟，不等同于 Excel 内部 COM 调用无限挂起。
- Release `open-data-audit` 构建成功。workspace 82 个测试目标：501 passed / 0 failed / 34 ignored。四个改动 Rust 文件 `rustfmt --check` 通过，Python harness `py_compile` 通过。未执行打包、push 或 Linux 验收。
- 全局 `cargo fmt --all -- --check` 仍会被无关既有文件的格式差异阻断；本轮只检查/格式化相关 Rust 文件。

## 结论和遗留

S1-F1 Windows COM 性能优化完成并停止迭代。Excel 冷启动是两边共同的主导开销；约 43 ms/批的 worker 启动/ready 额外成本不值得牺牲进程隔离，也没有证据支持继续做安全低成本优化。

本轮只测试合成重算工作簿，不是机构工作簿或 S1-F1 GUI 完整手工业务验收。真实机构输入、结果业务签收、Linux/Kylin/UOS 验收仍依项目 Goal 跟踪。S5 继续按用户要求暂停。
