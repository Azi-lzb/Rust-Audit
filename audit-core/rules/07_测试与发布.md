# 测试、验收与发布规则

> 本文件迁移自 Open-Data-Audit。根 AGENTS.md 的编译授权、人工验收和不主动全面对拍规则优先；以下验证层级描述实际开展相关验证时需要记录的证据，不能作为未经授权执行测试或阻止人工交付的要求。Python 测试脚本仅为基线/辅助；隔离 openpyxl worker 只用于既有工作簿修改，未验证能力可由用户显式试跑，但候选必须通过输出校验才可发布。

测试范围以 `AGENTS.md` 的功能变更要求为入口；本文件规定验证层级和报告证据。

## 测试选择

- 用户明确授权对应操作时，根据实际变更选择有意义的定向测试和必要验证；未授权时只作静态检查并明确列出未运行项，不自动开展全量 Python 对拍。
- 发布候选按用户授权范围执行必要检查；若产品启用隔离 openpyxl worker，还须在对应验收中验证内置 runtime、worker 协议、GLIBC 依赖和目标平台，不得依赖系统 Python。
- 按风险追加：脱敏/合成 fixture、文件结构与独立 reader 重开、Python/openpyxl 对拍、VBA/黄金业务基线对拍。公式重算由经授权的独立 ExcelCalculator 能力验收；同类转换由经授权的独立转换能力验收；Windows Excel/WPS COM 修改只可针对 ExcelModifier 中已实现且单独 capability-gated 的后端进行保真与语义验收。COM 修改必须经 ExcelEditPlan/ExcelModifier 显式路由。不得做打印/PDF 渲染验收。目标平台或旁路未执行时注明“未执行”。
- Sidecar 路径不得只靠 mock 宣布通过；旁路输出必须校验，未安装旁路时验证主路径可用且正确报告外部引擎缺失。
- 读取 Audit 现有配置时，使用 `audit-core/config-real/` 中已脱敏且本地保留的数据；缺失项才可使用公开占位配置。配置和真实工作簿均只读，修改场景先复制到临时目录，并记录实际配置来源。Rust 测试不得依赖旧 `core/tests/config_paths.py`。

## 必要证据

- 业务输出：相同输入和配置下，核对文件数量、数据数量、关键值与审核结论；日志/性能开关不得改变业务结果。
- 原始文件：重要流程执行前后比较 SHA-256，证明输入未被修改。
- 工作簿：验证预期公式、格式和结构；OOXML Patch 结果须通过包关系校验和独立 Rust reader 重开，Python/openpyxl 可作额外对拍。
- VBA/规则迁移：核对数量、启用规则存活率和触发行为；数量差异必须逐项解释，不能以“基本一致”代替。

## 报告格式

说明实际执行的命令/范围，并报告 `passed / skipped / failed / errors` 数量；列明新增或未新增测试的理由、真实数据验收结果及未执行的平台专属项目。不得把未执行写成通过。

## 性能优化

性能优化还要证明业务结果和文件结构未变。测量项以 `rules/09_技术实现参考.md` 的性能清单为准，至少保留输入规模、关键阶段耗时、输出差异和公式错误信息。
