### S1-F1 原生 COM 批次基准

该基准只覆盖 S1-F1 中由 Excel COM 打开、逐表计算、保存、关闭及后续缓存核验的步骤，不覆盖模板匹配、工作簿复制、异常提取和最终报告写出。

| 每批有效工作簿 | Python 批次中位数 | Rust 批次中位数 | Python/Rust | 每批 Excel 实例 | 正确性 |
|---:|---:|---:|---:|---:|---|
| 2 | 7,570.60 ms | 7,171.91 ms | 1.056× | 两边各 1 | 每引擎 5 批；另有损坏文件失败后继续处理的用例。 |
| 10 | 12,246.33 ms | 12,139.69 ms | 1.009× | 两边各 1 | 每引擎 2 批，成功输出 20 册。 |
| 33 | 27,006.11 ms | 27,138.94 ms | 0.995× | 两边各 1 | 每引擎 2 批，成功输出 66 册。 |

9 批/引擎各自复用一个私有 Excel 实例。总计 96 对输出的公式文本及结果哈希差异为 0；每册 6,000 个公式结果和 7,200 个缓存值均核验，输入哈希不变；worker 和所属 Excel 进程退出。两边随批量规模交替领先，按平价处理，不再为微小倍率继续优化。合成工作簿为每册 1,200 行、两张表，含 6,000 个 VLOOKUP 和 7,200 个非空缓存。

实例启动占主要成本：Excel 独立实例激活约 2.4–2.5 秒；Rust worker spawn 约 6.23 ms，ready IPC/启动残差约 37.17 ms。最终完整关闭等待 Excel 退出约 2.74 秒，已包含在批次计时中。阶段细节、异常处理和测试限制见 [S1-F1 COM 验收报告](probe/reports/s1f1_com_final_acceptance_20261030.md)。

口径说明：早期另有每册 7,200 个公式的热会话微基准，Python/Rust 在 `CalculateFull` 路径上约 3.5/4.7 秒；最终批量验收的每册负载为 6,000 个公式、7,200 个非空缓存，并完整计入 worker/Excel 进程退出等待。两组都是 COM 重算子步骤，不是相同负载，不能合并倍率，也都不构成 S1-F1 模板匹配至结果输出的整链路耗时。当前 COM 平价结论以最终 2/10/33 批次验收为准；早期逐轮证据保留在性能历史。

## 性能地图的覆盖边界

- 平台为 Windows x86_64。多数 A/B 测量使用合成负载；S2-F1 使用仓库测试夹具。没有 Kylin/UOS 或 Linux 性能结论。
- 2026-10-30 功能级对比以 Python 进程内计时对 Rust Release CLI 子进程墙钟计时；Python 不含解释器启动，Rust 包含约 21.8 ms CLI 启动。S1-F1 最终 COM 批次验收使用不同且已对齐的 worker/Excel 批次计时边界。
- S2-F1 原始夹具：两个唯一源 XLSX 为 6,033 和 4,974 字节，每个分别用于本期及上期，因此每轮传入 4 份文件副本；每期共 3 张源表。审核配置 `check_valid.xlsx` 为 8,451 字节、6 张工作表。其它合成运行没有把输入文件字节数写进 JSON，故不推算或补写。
- 各功能的处理记录数、工作簿数和输出规模列于表格；完整的输入字节数、所有 Sheet 数量并未由原始基准统一保存。新增基准应在生成 fixture 后记录真实字节数及表结构。
- Rust 业务模块已有不少阶段计时字段，S2 Web 也保存过真实阶段日志；但这些数值没有统一绑定到本次功能 A/B 的输入、Python 时长和 Release SHA，不能直接拼成当前版本的完整对照。下面单列已有观测。
- 所有功能统一口径的读取、清洗、规则计算、工作簿修改、保存和验证分段 A/B 计时仍未全部具备。S1-F1 现已在 acceptance 结果中提供微秒阶段计时，单轮覆盖请求/扫描、模板预检、结构对比、复制/编辑、真实重算、异常提取、结果写出及 Excel 会话关闭；当前仅有并发负载下的单轮分段诊断，不能回填到干净的三轮总耗时基线。S2 外部规则、S3-F2 放大规模、S3-F3/F4/F5 专项也分别记录了部分阶段。S1-F1 的结构预检与条件格式审核现已共享一次源工作簿读取投影；当前不跨公式复制/重算阶段缓存整簿投影，避免未经多文件峰值内存测试就持有多本工作簿。S3-F1 有用户确认的约 1.02×优化后对照，但优化后逐轮机器数据缺失。部分专项记录了进程树峰值工作集，不能代表完整的统一内存地图。
- S2-F1 基础仓库夹具性能轮只检查结构；S3-F2/F4/F5 的旧历史行没有完整值级对拍。新 S3-F2 放大规模、S3-F4 当前值级、S3-F5 有效表单专项都另有完整对拍，S3-F3 优化前后专项也完成值/公式/结构、备份及输入保护对拍。以对应专项证据为准，不把早期计时行升级为已对拍。
- 已有 Markdown 汇总与机器 JSON 部分不一致。此表对 S2-F1、S3-F2/F3/F4/F5 使用 `perf_comparison_20261030.json` 的逐轮值及其中位数；相应 Markdown 表仍作为历史记录保留。S3-F1 优化后采用性能优化报告给出的约 1.02×，并明确原始优化后逐轮 JSON 未找到。

## 优化排序与当前决定

1. **S1-F1**：COM 冷启动由 Excel 自身主导；2/10/33 册结果平价，正确性及进程清理均已验收。带模板结构区域的 4,000 行条件格式子流程已优化：指标组装从 15,523 ms 降到 57 ms，结构预检+条件审核内部事件耗时从 16,044 ms 降到 498 ms；随后共享一次源读取后五轮中位数再降至 390 ms，峰值工作集约 85.95 MB。完整 GUI 业务链已完成干净三轮对照，并新增微秒阶段遥测；最新分段仅是并发负载下的一轮诊断，不作为基线。实测大头仍为真实 Excel 重算和 Excel 会话退出，没有放松 COM 清理/隔离的低风险优化依据；不跨公式复制/重算阶段缓存整簿数据。
2. **S3-F1**：业务计算/输出验证优化后报告约 1.02×，完整验证保留。性能按用户要求暂结；后续不重复运行已完成比较。
3. **S2-F1**：CLI 冷启动令小夹具慢约 5.7 ms，但服务阶段快约 1.75×；外部核对结果已逐格对拍，不值得改业务路径。
4. **S3-F3**：已消除原地执行路径中临时 ExcelEditPlan JSON 的写入和立即读回；同负载内部耗时减少 78.54%，输出和备份对拍通过。现有 51 ms 未细分保护/发布工作保留，不为追求倍率继续削弱安全步骤。
5. **S1-F2、S3-F2/F4/F5**：当前样本明显快于 Python；S3-F2 放大到 2,610 条导出仍约 8.11×，全量值和结构比较通过，不做没有具体证据的重构。

此基线覆盖本目标内全部正式功能编号：S1-F1/F2、S2-F1、S3-F1 至 F5。性能基线不代表真实机构业务验收；各历史输入缺失、计时边界不一致和并发环境限制仍按表中证据边界解释。对当前已测规模，没有发现值得优先实施且不削弱正确性检查的未处理性能问题。

## 本轮目标完成审计

- **功能覆盖**：S1-F1/F2、S2-F1、S3-F1/F2/F3/F4/F5 均有 Python/Rust 总耗时对照或用户指定的暂结数据；输入规模、表/行/输出数量、结果核验及峰值内存按可得资料登记。已有内部阶段字段被用于定位瓶颈；缺失的阶段值不会以推算数字补写。
- **已实施的有效优化**：S1-F1 条件格式异常指标组装由 15,523 ms 降至 57 ms，结构预检与条件审核共用读取后阶段从 498 ms 降至 390 ms，模板结构投影读取从 528 ms 降至 224 ms；S2-F1 配置解析从 40 ms 降至 15 ms、21+21 批次保存阶段从 312 ms 降至 98 ms；S3-F3 移除原地执行路径的计划 JSON 写入/读回后，内部中位数从 946 ms 降至 203 ms。对应输出、输入保护及定向测试/对拍记录见各专项报告和性能历史。
- **未继续改动的功能**：S1-F1 COM 批次与 Python 平价，主要时间来自 Excel 冷启动、公式重算和受控退出；S3-F1 按用户要求以约 1.02×结项；S1-F2、S2-F1、S3-F2/F4/F5 在已测规模下 Rust 已明显快于 Python，S3-F3 优化后也有明显优势。剩余绝对耗时主要是结果写出或外部 Office 生命周期，当前没有兼顾低风险和明显收益的进一步改法。
- **证据限制**：S1-F1 完整链路的正式三轮总耗时/内存有效，但原始机器 JSON 曾被后续诊断覆盖，逐轮阶段日志等无法恢复；S1-F1 与 S1-F2 新阶段样本均在并发 Office 负载下，只用于阶段定位。旧 S2 21+21 真实输入和旧 S3-F2 真实工作簿未保留；S3-F1 优化后的逐轮 JSON 未找到。相关项保留在历史记录中并明确标为缺失，不影响当前合成/仓库夹具 A/B 结论，也不作为代码优化收益。
- **验证与仓库状态**：优化均有其对应的定向单元/业务测试、值级对拍或输入保护证据；各验证范围和未执行的全工作区/Linux 测试在历史中分别注明。测量记录关联当前 Git HEAD `7517a9c`，本工作区仍未提交；按项目规则，未经请求不创建提交、不 push。S5 排除。

因此，在本目标规定的 Windows 现有基准与合成/仓库夹具范围内，性能地图和有实测收益的优化已完成。将来获得新的代表性大批次或真实输入时，应以新的输入规模和独立报告复测，不覆盖本基线。
