## 终极根因（2026-11-07 补，与 Python 可开副本公式级对比确认）

与 Python 可打开副本（同源同模板）公式级 diff：

1. **W152/W153 同址不同式（杀手）**：Rust = `INDEX([1]集中系统数据!$1:$1048576,…`、
   `[1]参照表!…`——带 **`[1]` 外部工作簿引用前缀**；Python = `INDEX(集中系统数据!…`（已改
   本地引用）。导入外部表为本地 sheet6/7 后，公式里的 `[1]` 外链指向不存在的工作簿，
   Excel 打开即拒绝（0x80020009）；WPS 宽松忽略断链但重算丢公式（W152），完全吻合
   “WPS 报 重算丢失公式 存量债券投资!W152”。
2. Rust 独有 122 个公式（F100…）：模板校验区域公式写入源文件既有公式格之外的位置，
   Python 副本不含——非杀手（xlsx 级别合法），但属两侧副本内容差异，需业务确认口径。

## 修复方案

复制/导入外部表后，对全部 `<f>` 文本剥离外部工作簿索引前缀：正则 `\[(\d+)\]`
（仅当目标表名已存在于本包 sheets 时），与 Python“外链改内链”同口径。
落点：`ooxml_patch` 清缓存/导入管线（或 s1_formula_copy 副本准备阶段）；
同款 excel-open-repair 可扩展第三类缺陷（悬空外部引用）作为兜底。

## 责任链结论（谁引入的悬空外链）

| 环节 | 状态 |
|---|---|
| 模板 | 自带 `[1]集中系统数据!` 外链公式 12 处 + externalLink1.xml 定义（目标=`/0YYY/模板+外部文件202506/…` 旧机器绝对路径，断链），但有 `<v>` 缓存值兜底 → 模板语境自洽，Excel 打开显示缓存值 |
| 报送源文件 | 干净：W152 无公式（业务导出已固化），无 externalLink 部件 |
| 旧 Python 复制管线 | openpyxl 读写周期：读入时解析 `[1]Sheet!` 为外部链接对象，externalLink 目标断链时**丢弃部件并剥离公式 `[1]` 前缀** → 副本无 `[1]`、Excel 可开 |
| Rust 复制管线（已修） | ooxml_patch 写入模板公式原文 + 导入外部表为本地 sheet，但**丢弃 externalLink 部件却保留公式 `[1]` 前缀** → 悬空 → Excel 拒开 |

结论：模板"带病但自洽"；**悬空链接的直接原因 = Rust 复制管线丢弃外链定义却保留公式前缀**（旧 Python 同环节做了归一）。已修（第三类缺陷剥离），两类来源（模板外链/源文件外链）都覆盖。

- RustTools：需要提醒——自研 OOXML 副本管线（不经 openpyxl 周期）必须做 `[N]本地表名!` 剥离，可复用 Rust `excel_open_repair` 第三类实现
- 业务侧（可选）：模板公式改为本地引用或更新外链目标，但 Rust 修复后已不依赖

## 修复方案决策（用户确认，2026-11-07）

**默认断开所有外链（剥离 `[N]` 前缀），不保留/复制 externalLink 定义。**

理由：审核语义正确性优先于链接保真。若保留外链定义，`[1]` 引用虽可解析（合法断链），
但公式重算会回落到**模板缓存的外部旧值**（外链目标=旧机器断链路径，拉不到新数据），
审核结论将基于模板作者当时的数据快照而非本次导入的集中系统数据——语义错误。
剥离后公式指向本次导入的本地 sheet，与旧 Python 副本逐字节一致（W152 公式与值已实证）。

加固备查：当前剥离仅限"目标表名在本地存在"的 `[N]`；若出现引用未导入表的 `[N]`
（真·无关外链），剥离后重算变 `#REF!` → 按既有口径捕获为审核异常（优于整文件拒绝打开）。
